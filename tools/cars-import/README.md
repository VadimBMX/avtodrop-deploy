# Імпорт нових машин (сезон 2, номери 183–240 + 3 переробки)

Давид генерує картинки за брифом `avtodrop-mashyny-dlya-davyda.txt`: кузов **один рівний зелений #3FAE49**
(ключ для перефарбування), фон за брифом **рівний сірий #808080**. Конвеєр приймає і сірий, і зелений, і
нерівний фон — він визначає фон сам по краях картинки.

## Одна команда

```bash
npm run cars-import -- ~/Downloads/davyd-batch1        # тека або .zip-архів з Telegram
npm run cars-import -- ~/Downloads/davyd-batch1 --test # те саме + npm test у кінці
```

Далі: відкрити `tools/cars-import/out/sheet-*.jpg`, перевірити, закомітити (`git add public tools test`).
Нічого не пушиться і не деплоїться.

Що робить команда (`run.mjs`):

1. **`import.py <тека> --apply`**: вирізає машини, пише `out/report.json` і контактні аркуші, кладе в
   `public/cars/<id>.webp` усі картинки **без помилок** (`--force` бере всі).
2. **`register.mjs`**: додає машини в `public/shared.js` (згенерований блок `<cars-import>`), запікає
   фабричний колір і робить маску фарби (`tools/paint/green.py`), оновлює `car-photos.js`, мініатюри
   (`cars/thumb`), дані коліс для гонки (`race-wheels-data.js`).
3. **`import.py --sheet-only`**: перемальовує аркуші, тепер уже з фабричним кольором.
4. з `--test`: `npm test`.

На повну пачку з 61 картинки — кілька хвилин (rembg ~4 с на картинку).

## Що треба на комп'ютері

```bash
pip install numpy scipy pillow "rembg[cpu]"   # rembg — той самий, що й для npm run cars
# tesseract (необов'язково, для пошуку тексту/логотипів): apt install tesseract-ocr / brew install tesseract
```

Без rembg конвеєр працює на одному колірному ключі (сірий фон ріже чисто), але тінь під машиною прибирає
гірше — такі картинки позначаються на перевірку. Замість pip-пакета можна вказати теку з сумісним модулем:
`CARS_IMPORT_REMBG=/шлях/до/shim`.

## Що робить import.py з кожною картинкою

* **Фон**: модель фону з рамки картинки (рівний колір або плавний градієнт). Машина — це все, до чого не
  дістатись від краю по кольору фону, тому **зелена фарба всередині кузова ніколи не вирізається**, навіть на
  зеленому фоні.
* **Край**: м'яка альфа лише у вузькій смузі контуру; колір на краю очищається від фону (без сірого чи
  зеленого ореолу); зелений відблиск прибирається там, де край — не фарба (шини, скло, хром). Де контур
  кузова майже кольору фону (темне ребро капота на сірому), вирішує rembg.
* **Скло**: якщо крізь вікна видно фон (обрамлені ущільнювачами чи стійками, а не фарбою), скло лишається
  **напівпрозорим тонованим** (альфа ~0.55–0.85). Сірий відблиск на фарбі не чіпається.
* **Складні випадки** (фон кольору ключа, нерівний фон, ключ і rembg не згодні): силует від rembg.
* **Тінь / підлога / відображення** під колесами прибирається; машина вирівнюється по колесах (до 4°).
* **Напрямок**: усі машини в грі дивляться **вправо**. Напрямок визначається за силуетом (порівняння з
  усіма фото в грі; на наявних фото — 182/182 правильно) і за червоними задніми ліхтарями на зеленому кузові.
* **Розмір і полотно** — точно як у наявних фото (`tools/normalize_cars.py`): полотно 2.5:1, колеса на
  нижньому краю, машина торкається боків, ширина ~900 px (без збільшення), webp q86.
* **Маски фарби** окремо не потрібні: їх робить `green.py` під час `register.mjs` (машина = зелений ключ).

## Звіт: `out/report.json`

Для кожної картинки: `status` (`ok` / `warn` / `error`), `problems` (код, рівень, текст), `info` (фон,
метод, напрямок, розмір, частка зеленого, колеса). `error` = перегенерувати (у гру не йде без `--force`),
`warn` = подивитись на аркуш, `info` = виправлено автоматично.

| код | що означає | що робити |
|---|---|---|
| `cropped` | машина торкається краю картинки | перегенерувати |
| `wrong_angle` | не строго збоку (3/4, перспектива, нахил > 4°) | перегенерувати |
| `wrong_car` | пропорції не схожі на цей тип кузова | глянути на аркуш (евристика) |
| `low_resolution` | машина < 760 px завдовжки (< 560 = помилка) | перегенерувати у 2K/4K |
| `background_left` | ореол / шматки фону / сіра «дірка» в кузові | глянути на аркуш |
| `background_not_flat` | фон не рівний (градієнт, віньєтка, підлога) | зазвичай ок, глянути |
| `text_or_logo` | текст, логотип, номер, водяний знак | перегенерувати |
| `not_key_green` | кузов не зелений / дві фарби | перегенерувати (інакше не перефарбувати) |
| `green_parts` | зелені диски | перегенерувати |
| `see_through_glass` | світле прозоре скло | глянути; краще перегенерувати |
| `facing_uncertain` | не ясно, куди дивиться | глянути, за потреби `183f.png` |
| `flipped`, `levelled`, `shadow_removed`, `rembg` | виправлено автоматично | — |

## Контактні аркуші: `out/sheet-01.jpg` …

Рядок на машину: вихідна картинка · вирізка (зелена) · фабричний колір (після `register.mjs`) · дві машини
того ж класу з гри (схожий кузов) у тому самому масштабі. Кольорова смужка зліва — статус. **Аркуш — головна
перевірка на «не та машина»**: автоматика ловить лише грубу різницю пропорцій.

## Клас і ціна: `economy.json` (заповнює економіка)

```json
"bmw-m5-e60": { "cls": "B", "price": null, "prestige": 1, "homeOnly": false }
```

* `cls` — D / C / B / A / S. Зараз стоїть клас із брифу (заглушка). **X (секретна)** тут не підтримується:
  секретна машина — нагорода за колекцію країни (одна на країну), її додають у `SECRETS` вручну; Revuelto і
  Tourbillon поки що S.
* `price: null` — ціна між сусідами класу за потужністю/вагою та престижем (як `LATE_RAW`: **ціни інших
  машин не змінюються**). Число — фіксована ціна, має бути в межах класу.
* `prestige` −3…3, `homeOnly` — випадає лише з кейса своєї країни.

Після зміни `economy.json`: `node tools/cars-import/register.mjs` (перепише блок; ассети не чіпає, якщо
додати `--no-assets`). У `shared.js` ціни руками не пишуться.

`cars.json` — каталог пачки: номер, id (= slug назви, як у `shared.js`), назва, характеристики (к.с., вага,
кузов, рік, країна, ev), фабричний колір. Його правлять, якщо треба уточнити характеристики чи колір.

## register.mjs окремо

```bash
node tools/cars-import/register.mjs              # машини, що мають фото (і ті, що вже в блоці)
node tools/cars-import/register.mjs --all        # усі 58 + 3 у блок (без фото — чекають, у грі їх немає)
node tools/cars-import/register.mjs --ids 183,bmw-m5-f10 --no-assets
node tools/cars-import/register.mjs --reset      # забути старий блок
```

Машина без фото потрапляє лише в `PENDING_MODELS` (немає в кейсах, магазині, колекціях), як `NEW_RAW`. У кінці
друкується таблиця: клас, ціна, чи в грі, з яких кейсів випадає. Переробки (154, 089, 030) стають «ключовими»
лише тоді, коли прийшло їхнє зелене фото.

## Ручні правки: `overrides.json` (створити за потреби)

```json
{
  "183": { "flip": true },
  "233": { "gaps": "transparent" },
  "205": { "rembg": true },
  "190": { "accept": ["wrong_car", "not_key_green"] }
}
```

`flip` — примусово віддзеркалити / ні; `gaps` — `transparent` (прорізати сірі проміжки, напр. під
антикрилом) або `glass`; `rembg` — силует завжди від rembg; `accept` — пропустити ці помилки.

Інші ключі `import.py`: `--only 183,190`, `--rembg auto|always|never`, `--no-ocr`, `--out ТЕКА`,
`--sheet-only`.

## Самоперевірка

```bash
python -I tools/cars-import/selftest.py
```

Бере справжні зелені фото з `public/cars/base`, кладе їх на фон як у Gemini (1920×1080) і псує: віддзеркалення,
обрізання краєм, тінь, зелений фон, текст і водяний знак, низька роздільність, нахил, вигляд 3/4, не зелена
машина, позашляховик під номером купе, нерівний фон, прозорі вікна. Перевіряє, що кожну проблему знайдено,
а виправні картинки вийшли такими ж, як оригінал (збіг силуету IoU ≥ 0.95; на практиці 0.98–0.99), дивляться
вправо, стоять на краю полотна 2.5:1. Результат — `tools/cars-import/selftest-out/` (аркуші, звіт).
`public/` не змінюється.
